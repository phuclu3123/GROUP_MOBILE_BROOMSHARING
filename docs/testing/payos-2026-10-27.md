# Nghiệm thu tích hợp payOS và webhook WEB_TCC

Hoàn thiện ngày 27/10/2026 theo giờ Việt Nam. Phạm vi: backend Java, Firebase thật, QR payOS thật và tuyến webhook dùng chung WEB_TCC. Chưa thực hiện chuyển khoản ngân hàng hoặc tích hợp API hoàn tiền.

## Kết quả

| Phần nghiệm thu | Kết quả và giới hạn |
| --- | --- |
| Quyền backend Firebase | Tài khoản riêng `broomsharing-payments`; Firestore giới hạn database `broomsharing`, Firebase Auth chỉ đọc. Khóa JSON local bị Git ignore, không dùng refresh token cá nhân để chạy server |
| Rules cloud | Ruleset `7b974848-560e-4079-b328-1c4bf05dd47e`, đọc lại khớp nguồn local; bảy index giữ nguyên, không migration dữ liệu cũ |
| Android và dữ liệu thật | Một instrumentation test chạy 68,425 giây: Host demo tạo phòng/ảnh, Admin duyệt, Guest tạo booking, Host xác nhận, Guest lấy QR và mở Activity thật |
| Khoản trả trước | 40% của lượt thuê demo 5.000đ là 2.000đ. payOS tạo QR thật, API đọc lại vẫn PENDING, chưa nhận tiền |
| Kiểm soát nghiệp vụ | Trước xác nhận chưa tạo QR; Host không trả thay Guest; gọi lại giữ cùng orderCode; Rules chặn app tự ghi PAID/paidAmount |
| WEB_TCC production | Commit `d00716407350d1f61e253e1ad68e43b34bca962d` đã push main, Render được xác minh bằng `relayVersion=broomsharing-v1`. 81 test Node đã qua trước deploy |
| Đăng ký relay | Setup token đã được người dùng đồng bộ trên Render. Endpoint có token xác nhận đường chuyển tiếp tới Java. Không gọi API thay URL webhook của payOS |
| Tuyến webhook thực tế | Hai sự kiện hợp đồng do công cụ nghiệm thu tự ký đi qua WEB_TCC rồi Java; Java đối chiếu trực tiếp payOS và giữ trạng thái chưa thanh toán |
| Trường hợp sai | Chữ ký sai nhận 400 ở WEB_TCC; sự kiện có chữ ký nhưng sai số tiền bị Java từ chối, WEB_TCC trả 503 để không xác nhận mất sự kiện |

Sự kiện hợp đồng do công cụ thử tạo không phải bằng chứng ngân hàng đã chuyển tiền. Biên bản không đánh dấu booking PAID hoặc giả lập việc nhận tiền trên cloud.

## Dữ liệu và bản chạy demo

- Host: tài khoản `applicant.*`; Guest: tài khoản `guest.*` trong file local `data/demo/profile-identity-credentials.local.properties`.
- Phòng: `payos_demo_20261026_room`, địa điểm/giá ghi rõ DEMO, dùng ảnh minh họa của nhóm.
- Booking: `78cb225b84f342b8d0eb2b6dc88547bd6e48071c24e2366f907a257074419fa7`.
- Order payOS: `21887581577029`, khoản trả trước 2.000đ. QR này là link thật và có hạn theo booking.
- Backend Java đang chạy trên máy qua HTTPS tạm thời `https://permission-philips-quiet-modems.trycloudflare.com`.
- Đầu nhận webhook giữ ở WEB_TCC: `/api/payos/webhook` trên bản deploy web hiện có. WEB_TCC xử lý giao dịch khóa học như trước; các mã BroomSharing được chuyển về Java, Java vẫn kiểm chữ ký và đối chiếu payOS.

APK mới đã cài trên emulator. File mật khẩu cấp cho test đã được xóa khỏi thiết bị, test APK đã gỡ. Tài khoản Guest demo được giữ phiên để mở lại booking. Không thay role tài khoản Admin của nhóm.

## Cách chạy lại

Xem [hướng dẫn backend](../../backend/payments/README.md). `tools/payments/run-demo.ps1` khởi động Java và tunnel; `tools/payments/connect-relay.ps1` đăng ký lại đích với WEB_TCC bằng token setup. Mỗi lần tạo tunnel mới có thể đổi URL, cần rebuild APK và đăng ký relay theo URL mới. Máy và hai tiến trình phải còn chạy khi demo; đây chưa phải hosting Java liên tục.

Tài khoản server và Rules đã được phê duyệt riêng. Việc sửa/push main WEB_TCC và deploy relay production cũng đã được người dùng phê duyệt rõ. Không sửa checkout WEB_TCC cũ trong Downloads; bản thay đổi nằm trong clone riêng và trên GitHub.

Để nghiệm thu phần tiền thật, người dùng chủ động chuyển 2.000đ theo QR còn hiệu lực, sau đó kiểm tra webhook ngân hàng và booking/payment cùng ghi nhận. Công cụ không tự thực hiện chuyển tiền. Chưa có hoàn tiền tự động, payout nhiều Host hoặc thu nốt 60% qua API.

## Điểm còn mở tại thời điểm đưa mã nguồn lên GitHub

- QR đã gửi hạn tới payOS và backend chặn tạo yêu cầu sau giờ bắt đầu; giao diện chưa tự ẩn QR đúng thời điểm hết hạn. Listener hiện ưu tiên kết quả đã nhận tiền, cần bổ sung phản ánh trạng thái hủy/hết hạn.
- Khi tiền đến muộn nhưng booking vẫn CONFIRMED, cần kiểm tra thêm thời điểm giao dịch so với hạn thanh toán trước khi công nhận hợp lệ. Chưa coi các test EXPIRED mô phỏng là đã nghiệm thu chuyển khoản ngân hàng sau hết hạn.
- Thông báo chính sách hủy còn câu ghi cứng booking chưa thanh toán; cần đồng bộ với trạng thái tiền thật.
- Chưa chốt bắt buộc trả 40% trước check-in và cách xử lý khoản 60% còn lại. Không tự thêm các điều kiện này vào luồng cũ.
- Phương án đã chọn là chạy Java local. Khởi động lại tunnel có thể đổi URL, cần cập nhật cấu hình/build APK; không yêu cầu triển khai hosting Java trong bản này.
